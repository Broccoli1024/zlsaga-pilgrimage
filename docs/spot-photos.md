# スポット投稿写真

## 画面

- 地図のポップアップ: 最新の承認済み写真を1枚、100px高で表示。写真がなければ従来どおり。
- スポット詳細: 承認済み写真を24枚ずつ表示し、「さらに写真を見る」で全件を閲覧。拡大表示にも対応。
- 投稿フォーム・本人の審査状況は、現地情報・地図・チェックイン操作より下のページ末尾に配置。写真一覧は説明文の直後に表示。
- ログイン後の詳細: 1回1〜3枚の投稿、説明200文字、公開への同意、本人の投稿状態確認と削除。
- 管理ページの「投稿写真」: 確認待ち/公開済み/非公開/未完了の切替、承認・非公開化・削除、通報理由の確認。

## 保存

`supabase/migrations/20261017000000_spot_photos.sql` が追加するもの:

- `spot_photos`: spot_idで既存spotsに関連づける。user_id、画像パス、説明、審査状態、投稿日時・審査日時。
- `spot_photo_reports`: ログイン利用者の通報。1人1写真1件。
- 非公開Storageバケット `spot-photos`: JPEGのみ、1ファイル1MiB以下。
- RLSとRPC: 未承認写真は本人と管理者のみ閲覧。公開スポットの承認済み写真だけ匿名閲覧可能。一般利用者は承認状態を更新できない。
- 保存予約は利用者ごとのロック付きで最大30件（全スポット合計、未完了・非公開も含む）。
- 承認済みファイルの上書きは不可。削除はStorage削除後にメタデータを削除。

管理者判定は既存管理画面と同じメールアドレスを、DBのauth.usersの確認済みメールから照合する。ユーザーが編集できるメタデータは使用しない。
画像リンクは5分間のみ有効。画面は4分おきに更新する。非公開化後も既に発行したURLは最長5分有効。閲覧済みの画像そのものを回収することはできない。

## 圧縮

JPEG/PNG/WebP、元画像20MiB以下。ブラウザで長辺1600px以下に縮小しJPEGへ再描画、最大1MiBに圧縮。元のEXIF/GPS/ファイル名は送信しない。人物や車のナンバー等、画像に写る情報は自動で消さない。HEICは未対応。

## 導入

既存spotsや既存Storageポリシーを変更せず、追加マイグレーションのみ適用する。以前の未適用マイグレーションを一緒に流さないよう、適用対象を確認する。
新しいAPIキーや有料の画像変換APIは不要。既存のSupabase公開設定を使用する。無料枠は容量・通信量を管理画面で監視し、保証はしない。

未完了投稿は本人または管理者が削除可能。スポット/アカウントの削除時は関連するStorageオブジェクトも先に削除する運用が必要（DBのcascadeだけでは画像本体は消えない）。

## 検証

- `npm test` と `npm run build`
- ローカルPostgreSQL互換環境の権限テスト: `npm install --prefix /tmp/pilgrim-photo-tests --no-audit --no-fund @electric-sql/pglite` の後、`PGLITE_MODULE=/tmp/pilgrim-photo-tests/node_modules/@electric-sql/pglite/dist/index.js node scripts/photos/check-db.mjs`。リモートDBへは接続しない。Supabaseのauth/storageの最小スキーマを再現し、実際のマイグレーションとRLSを実行する。実Storageサービスとの疎通は別途確認が必要。
- UI仮データAPI: `node scripts/photos/mock-server.mjs`（127.0.0.1:54329のみ）。別のターミナルで `VITE_SUPABASE_URL=http://127.0.0.1:54329 VITE_SUPABASE_ANON_KEY=local-test-only npm run dev -- --host 127.0.0.1 --port 5183 --strictPort`。
- 仮データ画面: `http://127.0.0.1:5183/spots/a0000000-0000-4000-8000-000000000001`。ログイン画面では任意のダミー認証情報でテスト管理者としてログインする。実アカウントの情報は入力しない。テストAPIは認可を模擬するだけなので、権限検証には使用しない。

実DBへのテストユーザー・テスト写真の挿入は行わない。
