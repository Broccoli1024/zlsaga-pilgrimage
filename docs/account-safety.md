# 退会・投稿者の通報とブロック

## 退会

- マイページとメニューから `/delete-account` へ進める。Web用の案内URLは `https://pilgrimapp.jp/delete-account`（画面の本番デプロイ後に利用可能）。
- ログアウト状態でも削除対象・手順・問い合わせ先を読める。ログイン後は削除ページへ戻る。アプリの再インストールは不要。
- 現在のパスワード、削除対象への確認チェック、最終確認を要求する。
- `delete-account` Edge Function がトークンをSupabase Authで検証し、その本人の登録メールでパスワードを再確認する。呼出元が指定した利用者IDやメールを削除対象として受け取らない。
- サーバーのservice roleのみで実行。秘密鍵はフロントやGitに置かない。既存のSupabase実行環境変数を利用する。
- 削除ロックを作成し新規画像アップロードを停止。Storageの所有者・本人フォルダから画像を100件ずつ取得してStorage APIで削除。その後、利用ログとスポット統合バックアップ内の本人関連データを削除し、Authのユーザーを削除する。
- public.users、チェックイン・訪問履歴、ルート/ルート内スポット、滞在時間設定、アバター設定、投稿写真メタデータ、通報、ブロック設定は既存・追加FKのcascadeで削除。
- 途中失敗は503で明示し、同じ画面から再実行可能。失敗時も新規アップロードは止めたままにする。処理中の重複呼び出しは拒否し、3分後に再試行可能。完了時はロック行もcascadeで消える。
- 一部画像削除後に失敗する場合がある。完全な原子的処理ではない。実アカウントを検証目的で削除しない。
- 期限内のJWTが残っていても、削除済みアカウントのStorageへの新規書き込みを許可しない。

## 通報とブロック

- 写真一覧で、他人の投稿に「投稿者を通報」「投稿者をブロック」を表示。メールアドレスは出さず投稿者識別ラベルを使う。
- 通報の対象は写真IDからDB側で確定。本人による自己通報、未公開スポット/写真への通報は拒否。管理者だけが全通報を読み、写真の一括非公開化または対応済み処理を行える。
- ブロックは利用者ごとの設定。ログイン中の写真一覧と地図プレビューで対象投稿者の写真を隠す。マイページで解除できる。
- RLSでも他人のブロック設定の閲覧・改変を拒否し、ブロック対象の写真を除外する。管理者は審査のためRLS上の閲覧権限を維持するが、通常の一覧・地図ではフロントのクエリで自分のブロック設定を尊重する。
- ブロックは閲覧設定であり公開写真への匿名アクセスを制限するものではない。発行済み署名URLは最大5分、ダウンロード済みの画像は回収できない。

## 適用と検証

`20261018000000_account_safety.sql` のみ追加適用する。以前の未適用マイグレーションをまとめて適用しない。
`supabase functions deploy delete-account --use-api` で配置。verify_jwt=falseでも関数内部でgetUserを必須にしている。外部から任意のアカウントを削除することはできない。

- `npm test`: 本人確認・対象ID固定・削除順序・失敗時の中断と再試行。
- `PGLITE_MODULE=/tmp/pilgrim-photo-tests/node_modules/@electric-sql/pglite/dist/index.js node scripts/photos/check-db.mjs`: 実DBに接続しないローカルPostgreSQLのRLS、ブロック、通報権限、削除ロック、バックアップの削除範囲、cascade、失効前JWTの書込み禁止を検証。
- 本番Edge Functionは未認証リクエストの拒否まで疎通確認。実データ削除の確認は専用アカウントの利用について許可を得てから実施する。
- Play ConsoleにURLを登録する前に、Web本番デプロイ後の `/delete-account` の表示とログイン導線を確認する。
