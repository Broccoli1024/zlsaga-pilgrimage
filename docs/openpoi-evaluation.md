# OpenPOI API 導入検討（2026-10-13）

## 結論

ユーザーの判断により導入は見送り。以下は将来検討用の調査記録。

既存の聖地データを置き換えず、「周辺施設を探す」機能の候補として試す。
今回の地図UI改善にはAPI接続を組み込んでいない。

## 確認した公式情報

- https://openpoiapi.com/
- https://docs.openpoiapi.com/
- https://docs.openpoiapi.com/legal.html
- https://openpoiapi.com/attribution.html

現時点では無償・登録不要。商用利用可能だが、提供元ごとのライセンスと出典表示が必要。
検索はキーワード、中心座標・半径、矩形範囲に対応。入力補完もある。
結果には licenses と attributions が返る。保存時もそれらを保持する設計が必要。
座標のずれ、閉業施設の残存、観光名所の未収録などの制約がある。
提供形態・仕様変更、停止の可能性があり、サービス保証はない。

## 小さく導入する場合

1. 佐賀・唐津の飲食店、駅、公園のサンプル検索で精度と重複を確認する。
2. ユーザーが「この範囲で検索」を押した時だけ検索し、表示件数を制限する。
3. 外部施設は既存スポットと識別できるようにし、聖地と断定しない。
4. タイムアウト・件数ゼロ・API停止時も既存スポットとルート作成を維持する。
5. 結果と一緒に出典表示を実装し、位置や検索語の外部送信についてプライバシー説明を更新する。
6. 外部施設をルートに追加する場合は、既存DBのspot IDを前提とする保存処理を別途変更する。

ツイート本体は閲覧制限で直接取得できなかった。投稿URLを引用する検索結果からOpenPOI APIを特定し、上記公式ページで仕様と条件を確認した。
